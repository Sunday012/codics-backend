## 1. Executive Summary

This report documents the completion of **Phase B: PostgreSQL Migration via Prisma 7.10.0** for the CODICS backend. The legacy in-memory and JSON file persistence (`DataService` and `data/codics.json`) has been completely decommissioned and replaced with a fully relational, normalized PostgreSQL schema managed via Prisma ORM 7.10.0.

All API routes, parameter contracts, and response shapes were strictly preserved to guarantee seamless backward compatibility with existing frontend clients. Only additive improvements were introduced:
- `nextCursor` on paginated endpoints (`GET /notices`, `GET /past-questions`)
- Notice moderation endpoints (`PATCH /notices/:id/hide`, `PATCH /notices/:id/unhide`)
- Authenticated file download endpoints (`GET /assignments/:id/submissions/:subId/download`, `GET /past-questions/:id/download`)
- Public server time endpoint (`GET /time`)

## 2. Prisma 7 Architecture & Runtime Client Setup

Prisma 7 introduces architectural changes separating CLI migration tooling from application runtime client adapters. The CODICS backend is configured as follows:

### 2.1 Prisma Configuration (`prisma.config.ts`)
* Configures datasource URLs loaded via `dotenv`:
  - `DATABASE_URL`: Transaction pooler / application runtime database connection.
  - `DIRECT_URL`: Direct session connection used for CLI schema migrations and introspection.
* Configures migration output directory to `./prisma/migrations`.

### 2.2 Prisma Service & Driver Adapter (`src/prisma/prisma.service.ts`)
* Injects `@prisma/adapter-pg` using a node-postgres `pg.Pool`.
* Features smart connection configuration:
  - Local connections (`127.0.0.1` / `localhost`) disable TLS/SSL for fast local execution.
  - Remote / cloud connections (such as Supabase) automatically enable TLS (`rejectUnauthorized: false`) for secure pooling.
* Implements NestJS `OnModuleInit` and `OnModuleDestroy` hooks to handle graceful startup and connection pool drainage on server termination.
* Exposes clean query helpers and raw query execution with parameterized queries.

## 3. Relational Schema Architecture (`prisma/schema.prisma`)

The database schema models the complete academic and operational domain across 21 entities with UUID primary keys, audit timestamps, foreign key constraints, and relational indexes.

### 3.1 Entities and Models
1. **`Department`**: Academic department (`code` unique, `name`).
2. **`Setting`**: Singleton system configuration (`currentSession`, `currentSemester`).
3. **`User`**: System actors (`email` unique, `matricNo` unique, `staffId` unique, `fullName`, `passwordHash`, `role` enum, `departmentId`, `level`, `status`, `repTermStart`, `repTermEnd`, `activatedAt`, `lastLoginAt`).
4. **`Course`**: Academic course catalog (`code` unique, `title`, `units`, `departmentId`, `level`, `semester`).
5. **`Offering`**: Specific session offering of a course (`courseId`, `session`, `semester`).
6. **`CourseLecturer`**: Junction table assigning lecturers to course offerings (`offeringId`, `lecturerId`).
7. **`CourseRep`**: Junction table assigning course representatives to course offerings (`offeringId`, `studentId`).
8. **`Enrollment`**: Student enrollment in an offering (`offeringId`, `studentId`, `type` enum: `regular`, `carry_over`, `elective`).
9. **`Module`**: Weekly/topic course syllabus container (`offeringId`, `title`, `order`, soft delete `deletedAt`).
10. **`Material`**: Course material item (`moduleId`, `title`, `type` enum: `note`, `slide`, `link`, `past_question`, `contentOrUrl`, `fileSize`, `mimeType`, `status`, soft delete `deletedAt`).
11. **`Assignment`**: Academic assignment (`offeringId`, `title`, `description`, `dueDate`, `totalPoints`, `status`, `createdBy`).
12. **`Submission`**: Student assignment submission (`assignmentId`, `studentId`, `fileUrl`, `fileSize`, `mimeType`, `submittedAt`, `score`, `feedback`, `gradedAt`, `gradedBy`).
13. **`TimetableSlot`**: Course schedule block (`offeringId`, `dayOfWeek`, `startTime`, `endTime`, `venue`, `type`).
14. **`AttendanceSession`**: Class meeting session (`offeringId`, `date`, `sessionCode`, `isActive`, `expiresAt`, `createdBy`).
15. **`AttendanceRecord`**: Individual student attendance entry (`sessionId`, `studentId`, `status`, `markedAt`).
16. **`Notice`**: Departmental/course/level announcements (`title`, `content`, `priority`, `targetType`, `targetValue`, `authorId`, `isPinned`, `isHidden`, `expiresAt`, soft delete `deletedAt`).
17. **`PastQuestion`**: Past examination question bank (`courseCode`, `session`, `semester`, `examType`, `fileUrl`, `fileSize`, `mimeType`, `uploadedBy`, `isApproved`, `reviewedBy`, `reviewedAt`, `rejectionReason`, soft delete `deletedAt`).
18. **`ActivationCode`**: One-time student account activation credentials (`matricNo` unique, `codeHash`, `expiresAt`, `usedAt`).
19. **`RefreshToken`**: Session refresh tokens with family reuse detection (`userId`, `tokenHash`, `family`, `isRevoked`, `expiresAt`).
20. **`PasswordReset`**: Single-use password recovery requests (`userId`, `tokenHash`, `expiresAt`, `usedAt`).
21. **`AuditLog`**: Append-only compliance trail (`actorId`, `action`, `entityType`, `entityId`, `payload`, `ipAddress`, `userAgent`, `createdAt`).

### 3.2 Schema Safety Features & Custom SQL Applied
In migration `20261016123559_init_r1`, custom SQL was appended to ensure database-level guarantees beyond Prisma schema capabilities:
1. **Partial Unique Index on `PastQuestion`**:
   ```sql
   CREATE UNIQUE INDEX "uq_past_question_active"
   ON "PastQuestion"("courseCode", "session", "semester", "examType")
   WHERE "deletedAt" IS NULL;
   ```
   Ensures duplicate exam uploads are rejected without preventing re-upload if a previous version was soft-deleted.
2. **Immutable `AuditLog` Triggers**:
   ```sql
   CREATE OR REPLACE FUNCTION prevent_audit_modification()
   RETURNS TRIGGER AS $$
   BEGIN
       RAISE EXCEPTION 'AuditLog records are append-only and cannot be modified or deleted.';
   END;
   $$ LANGUAGE plpgsql;

   CREATE TRIGGER trg_auditlog_immutable
   BEFORE UPDATE OR DELETE OR TRUNCATE ON "AuditLog"
   FOR EACH STATEMENT EXECUTE FUNCTION prevent_audit_modification();
   ```
3. **Row-Level Security (RLS) & Role Permission Revocation**:
   All 21 tables have `ENABLE ROW LEVEL SECURITY` executed, and all privileges (`ALL`) are revoked from Supabase public roles `anon` and `authenticated`. All data access must pass through the backend NestJS service role.

## 4. Security & Hardening Enhancements

1. **Database-Backed Account Activation (`ActivationCode`)**:
   - Activation codes generated with high-entropy cryptographic strings.
   - Stored in database as Argon2 hashes.
   - 7-day expiration window.
   - Single-use consumption (invalidated upon activation).
2. **Refresh Token Family Rotation (`RefreshToken`)**:
   - Opaque 64-character cryptographic tokens.
   - Tokens stored as SHA-256 digests.
   - Associated with a `family` UUID.
   - Refreshing yields a new token within the same family and marks the prior token revoked.
   - If an already-revoked token is presented (reuse attempt), all tokens in the entire family are immediately invalidated, protecting compromised sessions.
3. **Password Reset Token Flow (`PasswordReset`)**:
   - 1-hour expiration.
   - Tokens stored as SHA-256 hashes.
   - Single-use consumption (`usedAt` recorded).
   - Generates audit log on trigger and completion.
4. **Password Hashing**:
   - Password hashes generated and verified exclusively using `argon2id` (v0.14.x).
5. **Soft Delete Preservation**:
   - Deleting a course module cascades soft-deletion (`deletedAt = now()`) to all contained materials.
   - Deleting a notice or past question marks `deletedAt = now()`, excluding it from all public queries while maintaining auditability.
6. **Past Questions Upload Permission Matrix**:
   - Admin, HOD, and Lecturer: files immediately approved (`isApproved = true`).
   - Active Course Rep (`repTermStart <= now <= repTermEnd`): uploads enter pending state (`isApproved = false`) requiring HOD/Admin review.
   - Students & Expired Course Reps: forbidden (HTTP 403).

## 5. Storage Architecture & Secure File Delivery

1. **Disk Storage Driver (`src/common/storage.service.ts`)**:
   - Files stored on local disk under gitignored directory `./uploads`.
   - Files named via secure UUID prefixes, completely preventing directory traversal attacks (`../`).
   - Validates maximum file sizes (15MB for past questions and assignments).
   - Validates MIME types (PDF, PNG, JPG, DOCX).
   - Eliminates legacy base64 data URIs from the database.
2. **Authenticated File Download Routes**:
   - `GET /api/v1/assignments/:id/submissions/:subId/download`: Verifies that the requester is the student who submitted the file, or an instructor/rep/admin for the offering.
   - `GET /api/v1/past-questions/:id/download`: Verifies authenticated user access, streams the file from disk with proper `Content-Type` and `Content-Disposition: attachment; filename="..."` headers, and returns 404 if the file is soft-deleted.
